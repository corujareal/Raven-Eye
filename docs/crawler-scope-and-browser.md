# Crawler scope and browser egress

The legacy and async crawlers constrain requests to the exact seed host by default. Add a domain to `--scope` or the scope file to include that domain and its subdomains; use `*.example.org` for subdomains while excluding the apex. The legacy HTTP client rechecks each redirect against both the allowed hosts and excluded URL patterns before following it.

The async crawler does static JavaScript and source-map analysis by default. Its optional headless mode is enabled with `raven crawler URL --engine async --headless` or `headless_rendering: true` in configuration. It renders only pages matching strong SPA shell markers, uses the same host allowlist plus URL path/regex/exclusion checks, and records runtime XHR/fetch methods, sanitized URLs, and response status without storing request bodies. Only GET and HEAD browser requests are allowed; OPTIONS and state-changing methods are aborted before leaving the browser. Forms are never submitted. Images, media, and fonts are skipped during rendering to bound time and bandwidth.

The headless renderer runs Chromium with its sandbox enabled behind the loopback `SafeSocksProxy`; the proxy validates public DNS answers and connects to a pinned address. Browser request routing enforces path-level scope. Service workers are blocked so they cannot bypass request routing. WebSocket URLs are recorded through Playwright routing, but the remote connection is mocked and no messages are forwarded. The `headless_max_pages`, `headless_timeout_ms`, `headless_wait_ms`, `headless_max_events`, and `headless_concurrency` settings bound browser work. Headless rendering is off by default, and missing Playwright or browser runtime produces a per-page error record rather than silently claiming coverage. The RavenEye CLI currently rejects `--proxy` with `--engine async`; it does not silently bypass a configured proxy.

Playwright 1.48 or newer is required for scoped WebSocket routing. The renderer uses Chromium; RavenEye does not launch Firefox or WebKit. Linux installs prefer the distro's native Chromium where a package-manager adapter is known, and launch falls back to it if the bundled Playwright executable cannot start. Static mode remains available without launching a browser.
